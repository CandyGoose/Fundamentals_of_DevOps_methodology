## 1 часть

Плохой Dockerfile - [Dockerfile.bad](./Dockerfile.bad), нормальный - [Dockerfile.good](./Dockerfile.good).

### Лишние пакеты

```Dockerfile
RUN apt-get update && apt-get install -y \
    openssh-server \
    telnet \
    vim \
    curl
```

Тут openssh, telnet, vim - приложению не нужны, зато образ толстеет и дырок больше. В хорошем оставила только то, без чего контейнер не стартует.

### Секрет в ENV

```Dockerfile
ENV DB_PASSWORD=super_secret_password
```

Пароль осядет в слоях образа. Запушу на GitHub - из истории уже не вычистить, только менять пароль. В хорошем секрет передаю при docker run, в образ не кладу.

### Лишние порты

```Dockerfile
EXPOSE 22 80 443 8080
```

Приложению нужен только 8080. 22 (ssh) тут вообще лишний - лишняя дверь наружу. В хорошем:

```Dockerfile
EXPOSE 8080
```

### Публикация порта наружу без необходимости (работа с контейнерами)

```bash
docker run -p 8080:8080 myapp
```

Так сервис слушает на всех интерфейсах хоста, не только localhost. Для локальной разработки обычно хватит:

```bash
docker run -p 127.0.0.1:8080:8080 myapp
```

Снаружи до контейнера не достучаться.

### Запуск контейнера без лимитов ресурсов (работа с контейнерами)

```bash
docker run myapp
```

Контейнер может съесть всю память или cpu и положить остальное на машине. Задала лимиты:

```bash
docker run --memory=256m --cpus=1 myapp
```

## 2 часть

Плохой compose - [docker-compose.bad.yml](./docker-compose.bad.yml), нормальный - [docker-compose.good.yml](./docker-compose.good.yml).

### Использование latest

```yaml
image: nginx:latest
image: redis:latest
```

latest плавает. Сегодня подтянулся один образ, завтра другой - и дебажить непонятно что изменилось.

```yaml
image: nginx:1.27-alpine
image: redis:7.4-alpine
```

### Запуск сервисов с избыточными привилегиями

```yaml
privileged: true
```

Контейнер получает почти права хоста. Взломали приложение внутри - дальше проще добраться до машины. Убрала privileged.

### Нет volume для данных БД

```yaml
services:
  db:
    image: redis:latest
```

Контейнер удалю - данные redis пропадут. Подключила volume:

```yaml
services:
  db:
    image: redis:7.4-alpine
    volumes:
      - redis_data:/data
```

### Достигаем изоляции

app сидит только в app_net, db только в db_net. Обе сети internal: true, общей сети нет.

```yaml
services:
  app:
  ...
  networks:
    # Отдельная сеть для app
    - app_net

  db:
  ...
  networks:
    # Отдельная сеть для db
    - db_net

networks:
  app_net:
    driver: bridge
    # Внутренняя сеть без внешнего доступа
    internal: true
  db_net:
    driver: bridge
    # Внутренняя сеть без внешнего доступа
    internal: true
```

Compose поднимает оба контейнера одной командой, но они в разных bridge-сетях. DNS docker работает внутри сети - app не резолвит db, db не резолвит app.

## Выводы

Сделала пару Dockerfile и два compose - специально кривые и нормальные. Из Dockerfile вынесла лишние пакеты, пароль из ENV, лишние порты. Отдельно - не публиковать порт на 0.0.0.0 и не запускать без лимитов.

В compose зафиксировала версии образов, убрала privileged, добавила volume для redis. В хорошем варианте app и db в разных internal-сетях - поднимаются вместе, но друг друга по сети не видят.
